# compare v0: bgsub against pyREyes and XDS/superxds on real Apollo frames (2026-11-05)

Owner's question (2026-11-05, in conversation): speed gates are relative (single-CPU Python); the question is whether
the subtraction WORKS and how efficient it is overall, compared with superxds (github.com/XMB5/superxds, Fortran) and
pyREyes (github.com/theNelsonLab/pyREyes) on 1024^2 and 2048^2 images: how many peaks each finds, the intensity
distribution of the found peaks, the peaks mapped back onto the original image, how intensities change after the
background subtraction, and what mechanism each uses. External tools are used here as REFERENCE MEASUREMENTS (the
"no other packages" rule concerns the methods, not the yardsticks). Nothing here is pre-registered: it is a first
descriptive comparison; its numbers are not validity verdicts.

Code: `scripts/compare_v0.py` (stages select, bgsub, pyreyes, xds), `scripts/compare_v0_eval.py` (common per-peak
table, matching, radial residuals, figures). Outputs with provenance sidecars: `~/pod_data/bgsub/compare_v0/`.
Figures: `notes/figures/compare_v0/`. External clones (read-only reference): `pod/python_packages/superxds` (commit
77e4537 line), `pod/python_packages/pyREyes` (3.6.3, c0681ee). Anomalies here are numbered B1, B2, ...

## 1. The three mechanisms

### 1.1 bgsub (this project; v2.1 global estimator G2.1 used here, v1 run alongside)

One frame, stored counts. Sufficient statistics on polar cells (1-px rings x 64 sectors x 2 checkerboard halves); a
linear smooth model (fine radial cubic B-spline + azimuthal harmonics m <= 6 on a coarse radial spline + centre /
ellipticity derivative columns + penumbra columns next to the stop; v2.1: re-centring and an elliptical 1-px ring
refinement); cross-fitted weighted least squares with the count-law variance taken from the other half, so the estimate
is linear in the counts and unbiased for ANY count law when the truth is in the span. Spots, hot pixels and zingers are
excluded by one-sided count-law tests (alpha 1e-6 per pixel and per 3 x 3 window, dilated). Declared detector law:
Apollo bin 8 (round-half-even of the 3-raw-frame electron sum / 4, tie rule 0.35 with gain on, paralyzable dead time),
Apollo bin 4 (1 e per count, dead time) with the TIFF pedestal declared as an offset of 1 (`CountLaw.with_offset(1)`).
bgsub does not find peaks (background only). For the peak questions two lists are reported: (i) `bgsub_flags`, the
components of its exclusion flags (what the fit leaves out; conservative by design); (ii) `bgsub`, a plain, declared
detector on the subtracted image: 3 x 3 box excess (K - B) >= 5 sigma of the 3 x 3 count-law variance at B, 8-connected
components with at least the same minimum pixels as pyREyes (3 at bin 8, 5 at bin 4). No DoG, no tuning.

### 1.2 pyREyes 3.6.3 (`src/pyREyes/dif_map.py`, class ImageProcessor)

There is NO background model. The frame (float64) is band-passed by a difference of Gaussians, D = G(sigma_l) * I -
G(sigma_h) * I (`create_binary_image`, dif_map.py:438-441), thresholded globally at mean(D) + k std(D) (442-444), 3 %
of each edge blanked (447-453); peaks = 8-connected components of the binary image with area >= min px
(`get_centroids`, 471-486; skimage `label` / `regionprops_table`), centroids inside a central square box of half-width
0.25 x (half frame) dropped (488-498; `exclude_center=25` at 562). Parameters: 2048 px frames, config
Arctica-Apollo-SM (`config/microscope_configs.json`): sigma 1 / 5, k = 10, min 5 px; frames < 2048 px
(`SMALL_FRAME_PARAMS`, dif_map.py:59-64): sigma 1 / 3, k = 6, min 3 px. Per peak only (row, col, area) exist; NO
intensity is measured (`process_mrc_file` keeps only the count, 560-564), and the DoG image is not returned. The
second stage ("LQP", FFT of the binary mask) and the Grid / No / Poor / Bad / Good labels are downstream of the count.
Input: MRC only (`load_diffraction_frame`), but the scoring takes a bare 2-D array, which is what is used here. The
harness re-implements lines 419-502 exactly (`compare_v0.pyreyes_detect`); verified bit for bit against the real
functions (binary masks and centroid lists identical) on 2 bin-8 and 2 bin-4 frames of this set.

### 1.3 superxds (github.com/XMB5/superxds) = XDS; run here as XDS

superxds is a Fortran + C re-implementation of the whole XDS pipeline (XYCORR ... CORRECT) driven by XDS.INP, "the same
results as the original" per its own source comments, with AVX-512 C kernels and OpenMP in place of forked jobs. It
DOES NOT BUILD on this Mac (arm64, Homebrew gfortran / gcc 15): its build script demands GCC >= 16; with that gate
lowered all 69 Fortran files compile but the C stage needs glibc (`sincosf`, `malloc.h`, `st_mtim`) and unconditional
`__m512` / `immintrin.h` (B1). It is Linux x86-64 only as written. The installed XDS (`/usr/local/bin/xds`, VERSION Apr
16 2026) is therefore the executable stand-in; the mechanism below is read from the superxds source (file:line in
`src/`), which is the readable form of the same algorithm.

Background, two layers. (a) INIT builds a static per-pixel table BKGINIT.cbf from the BACKGROUND_RANGE frames: at every
4th pixel a (2 NBX + 1)^2 = 7 x 7 box mean of the valid pixels and gain = box variance / mean (Poisson assumption;
initialization.f90:1036-1055); gains above median + 4.88 MAD are reset, dropped nodes refilled from a running box
mean (1058-1110); node values averaged over the frames, bilinearly interpolated, stored x 1000 (563-658). (b) COLSPOT
per frame (frame_handling.f90 MARKPIX2:411-640): a sliding 7 x 7 box; a pixel is a CANDIDATE (non-background) iff its
box variance exceeds (box mean) x gain x FAC, FAC = 1 + BACKGROUND_PIXEL x sqrt(4 / 48) (457, 593-595); the frame's
background is BKGINIT x RATIO with ONE scalar per frame, RATIO = sum(frame) / sum(BKGINIT) over the non-candidate
pixels (605-616; 823). Spots: a candidate pixel is STRONG when its Poisson one-sided excess over E = BKGINIT x RATIO
(quantile from an NCUT table, 852-879) gives SCORE = (I - E) / gain / sqrt(V) > SIGNAL_PIXEL (813-848); strong pixels
are joined across rows and frames (union-find, joincolspot.f90:562-684); a class is a spot if it has >=
MINIMUM_NUMBER_OF_PIXELS_IN_A_SPOT pixels and its centroid lies within SPOT_MAXIMUM-CENTROID of its brightest pixel
(834-866). The reported "intensity" of a spot is the SUM OF THE PIXEL LABELS, label = min(10 x SCORE, 127): a sum of
significance scores, not background-subtracted counts; no sigma (846-864). Input formats: CBF, TIFF (one strip), SMV,
..., no MRC. Settings used here: XDS defaults (BACKGROUND_PIXEL 2, SIGNAL_PIXEL 3, 6 px per spot) as the primary, and
the owner's electron XDS.INP for mov11 (4 / 7 / 5) as the variant.

## 2. Frames

- bin 8 (1024^2, Apollo fly-scan, 49-ms stored frames, gain flag on): 30 frames from the cached atlas spot-test set
  (`~/pod_data/background/frames/atlas_spots_v0_<sid>.npz`): for each of s73dc36c8 and s8bdcf271, 10 REyes "Good
  diffraction" + 5 "Bad diffraction" frames, seed 0. Background ~0.07-0.08 stored counts per pixel (the sparse regime).
  Centre from the features table, mask = session stop + arm (shells mask) dilated 1 px, seams, 2-px border.
- bin 4 (2048^2, Apollo classic rotation movie x08 m0 = "mov11" of xds_merge_v0, CL 420, 1 deg per frame, TIFF = MRC + 1):
  frames 1, 13, ..., 109 (10 of 120). Background 0.1-5 counts per pixel above the pedestal. Beam centre (row 1028.5,
  col 954.5) from Friedel pairs of the 1135 spots of the owner's XDS run (492 paired at 2 px); the image-symmetry centre
  (1036, 952-959) agrees in column; the XDS.INP ORGX / ORGY (1030 / 1020 -> 1019.5 / 1029.5) was never refined
  (XPARM = GXPARM = INP) and is 75 px off in column (B2). Stop = ~100-px disc + arm to the left; it is not opaque to the
  pedestal rule (stray counts inside), so the mask is a low-local-mean rule on the 10-frame sum (`masks/bin4_mov11.npz`).
- Reference at bin 4: the owner's XDS run (`xds_merge_v0/private/runs/probe_mov11_V0/SPOT.XDS`, 4 / 7 / 5), 100 spots on
  the selected frames ("xds_ref").

Common per-peak measurement (`compare_v0_eval.py`), on the ORIGINAL frame, in a disc of radius 3 px (bin 8) / 5 px
(bin 4) about each method's centroid: S_raw = disc sum of the stored counts; B_<m> = background under the disc by
estimator m (bgsub v2.1 / v1 maps + the declared offset; XDS = BKGINIT / 1000 x the per-frame RATIO recomputed with
COLSPOT's rule outside every detected spot; FLAT = annulus [rb + 2, rb + 6] MEAN x disc pixels, the XDS / DIALS-style
local background; the annulus MEDIAN is kept as a side column because it is 0 at sparse counts); I_<m> = S_raw - B_<m>;
frac_<m> = B_<m> / S_raw. Matching between methods within 3 px (bin 8) / 4 px (bin 4), xds_ref within +-1 frame.
Radial residuals: mean (K - B) / mean K per 32-px band over pixels outside every method's discs, the flags and the mask.

## 3. Does the subtraction work? Background on spot-free pixels (`radial_residuals.csv`, `radial_residuals.png`)

Mean (K - B) / mean (K - zero level) per 32-px radial band over pixels outside every method's peak discs, the flags and
the mask, averaged over frames:

| background | bin 8, r 64-512 px | bin 4, r 128-512 px | bin 4, r 768-1408 px |
|---|---|---|---|
| bgsub v2.1 | -0.6 % ... +0.3 %, every band | 0.0 % every band (|.| <= 0.1 %) | 0.0 ... +0.3 % |
| XDS BKGINIT x RATIO | +0.6 ... -8.3 % (r < 400), +54 ... +64 % at r > 448 (where counts are ~0.002 / px) | -12 ... -14 % at r 128-320, -9 ... -5 % at 320-512 | +5 ... +51 % |
| local mean, same footprint as the annulus | ~0 by construction (it is fit to the same pixels; not a test) | same | same |

bgsub's background matches the data in every band at both binnings; at bin 8 the mean of K and of the model agree to
1e-4 counts per pixel in every band and the count-law variance g(B) equals the empirical variance band by band (e.g.
r 250-350: mean 0.0417 / 0.0416, variance 0.0400 / 0.0397), i.e. the law and the fit are both right in the sparse
regime (Pearson dispersion 1.016 at bin 8; 1.33 at bin 4 where the many weak spots and the halo structure next to the
stop inflate it). XDS's static table times one scalar per frame cannot follow the frame: it under-estimates the halo
(-9 to -14 % inside r ~ 400 px at bin 4) and over-estimates the far tail; at bin 8 its gain and ratio come from a few
hundred "background" pixels (Sec. 1.3, B3). The TIFF pedestal enters XDS's INIT gain (0.41 at bin 4, A184); bgsub
declares it (offset 1) and the residual is exactly the pedestal before the offset is added back (B4: `res.bg` is
returned WITHOUT `law.offset`; the evaluation adds it).

Readings. (i) bgsub's list contains most of what the other two find (74-87 % of XDS's and pyREyes' peaks at bin 4,
74 % of XDS's at bin 8) and 2-4 x more besides. What it alone finds is weak and real-looking: bin 4 lone peaks have a
median disc sum 209 counts, net 71, max pixel 9, component z 9.1, at a median radius 686 px (the high-angle region of
a small-molecule pattern to 0.78 A), against shared peaks with net 315 and max pixel 30; the overlay shows them on
faint spots, not on noise. They are not verified against truth here. (ii) pyREyes at bin 8 is at the noise floor of
its own statistic: its peaks that bgsub does not confirm (278 of 592) have a median disc sum of 4 counts and a maximum
pixel of 1 (single stray electrons grouped by the sigma-1 blur), and it finds as many peaks on REyes "Bad" frames (17)
as on "Good" ones (14); it also fires on the beam-stop edge and arm tip (47 of 639 peaks on the mask at bin 8). At bin
4 it is a reasonable bright-spot finder (median max pixel 34), consistent with XDS (58 %). (iii) XDS COLSPOT does not
operate on single sparse bin-8 frames: every single-frame run ends with "INSUFFICIENT NUMBER OF SPOTS" (NBKG ~ 500 of
1 M pixels, NSTRONG 0 at SIGNAL_PIXEL 7); a 15-frame pseudo-sweep with XDS defaults yields ~4 spots per frame. At bin
4 with defaults it finds 46 per frame (5444 over the 120 frames); with the owner's 4 / 7 / 5 it finds 9 per frame
(938), the reference run. (iv) Hygiene: bgsub's filtered list still has 98 components touching the mask at bin 4
(the halo next to the stop, where the dispersion is 1.33); they are excluded from every statistic above by `on_mask`.
Adjacent spots merge into one flag component after dilation (median area 104 px at bin 4), which costs some matches
(B5); a proper peak finder would split them, but peak finding is not bgsub's product.

## 6. Efficiency (this Mac, single process; bgsub numba; XDS 4 threads)

| per frame | bgsub v1 | bgsub v2.1 | pyREyes DoG + label | XDS XYCORR + INIT + COLSPOT |
|---|---|---|---|---|
| bin 8, 1024^2 | 105 ms | 62 ms | 31 ms | 33 ms (15-frame pseudo-sweep: 0.5 s) |
| bin 4, 2048^2 | 138 ms | 155 ms | 149 ms | 125 ms (120-frame sweep: 15 s) |

Plan construction (cached per geometry and mask) 0.3 s at 1024^2, 1.2 s at 2048^2. bgsub is within a factor 1-2 of
the Fortran COLSPOT per frame and of pyREyes' two Gaussian blurs, while doing a full model fit; the owner's point
stands that single-CPU Python timings are relative numbers.

## 7. Summary

- The subtraction works on real frames at both binnings: bgsub's background is unbiased to < 1 % in every radial band
  (1e-4 counts per pixel at bin 8) with the count-law variance confirmed empirically; the XDS / superxds background (a
  static table x one scalar per frame) is 9-14 % low in the halo and high in the tail at bin 4 and collapses at bin 8;
  pyREyes has no background estimate at all (band-pass + threshold).
- Peaks: bgsub's count-law flags recover 74-87 % of what XDS and pyREyes find plus 2-4 x more weak, high-angle candidates;
  pyREyes at bin 8 counts single stray electrons and the stop edge; XDS COLSPOT needs its default thresholds and a sweep
  to run at bin 8 at all.
- Intensities: against bgsub, a flat local background removes 15 % more "background" and loses 5-14 % of the net
  intensity at the median, up to ~17 % on bright spots; the XDS table happens to agree under peaks.
- Efficiency: 62-155 ms per frame in Python/numba, same order as COLSPOT and the DoG.

## 8. Limits and anomalies

- Not pre-registered; no truth for the real peaks (the injected-peak harness is the place for that); 40 frames, two
  bin-8 sessions and one bin-4 movie; the bgsub detector and the matching tolerances are declared choices.
- B1: superxds does not build on macOS/arm64 (GCC >= 16, AVX-512 kernels, glibc); XDS used as the stand-in. Running
  superxds itself needs a Linux x86-64 box (owner's call; not on the HPC).
- B2: the mov11 XDS.INP beam centre (1030 / 1020) was never refined by XDS and is 75 px off; the Friedel-pair centre
  (1028.5, 954.5) is used. This does not affect XDS COLSPOT (no geometry) but does affect bgsub's plan; the XDS merge
  study's IDXREF/INTEGRATE used the wrong origin (to be checked there).
- B3: XDS COLSPOT's variance screen keeps 0.07 % of the pixels as "background" at bin 8 (8 % at bin 4 with defaults).
- B4: `res.bg` excludes the declared offset (documented in core.py:556); evaluation code must add it back.
- B5: dilated flag components merge adjacent spots; 98 filtered components touch the mask at bin 4.
- B6: the pyREyes re-implementation was verified bit for bit on 4 frames only; parameters per shape as in 3.6.3.
